# 概要

**arthash** はプレースホルダー画像ハッシュのファミリーです。とても短いバイト列（17 B 〜 400 B）が、元画像の認識可能なプレビューにデコードされます。使い方は [blurhash](https://blurha.sh/)、[thumbhash](https://evanw.github.io/thumbhash/)、[sqip](https://github.com/axe312ger/sqip) と同じ—画像 URL の隣にハッシュを保存し、本物の画像がロードされる間にプレビューを即座にレンダリングします。

コアは Rust で書かれており、Python は PyO3 wheel、TypeScript は wasm-bindgen 経由で同じ Rust コードを再利用します。どのバインディングで生成したハッシュも、他のすべてのバインディングでデコードできます。

## 何を置き換えるか

| 現在使っているもの     | arthash でこう置換               | 主なメリット                                                  |
| ---------------------- | -------------------------------- | ------------------------------------------------------------- |
| blurhash / thumbhash   | `DCT` モード                     | 同じバイト予算で PSNR +0.4 dB、JS エンコード 1.9× / デコード 1.4× |
| sqip（primitive 部分） | `TRIANGLE` / `CIRCLE` モード     | サイズ 1/9 〜 1/16、エンコード 50–67× 高速、ブラウザ wasm で動作 |

shape / `PIXEL` モードは外部パレットも受け取れます。形状ごとの色フィールドを 4 bit に圧縮し、出力に自然な視覚スタイル（ブランドカラー、レトロ、モランディなど）を与えます。

## モードの選び方

| ゴール                                      | 選ぶモード                                       |
| ------------------------------------------- | ------------------------------------------------ |
| 可能な限り小さいバイト、ぼやけた見た目      | `DCT`（≤ 24 B）                                  |
| 鮮明な形状、SVG プレビュー                  | `TRIANGLE` / `CIRCLE` / `RECT`（`n` に応じ 50 – 400 B） |
| レトロ / ブランド一貫のプレースホルダー     | 任意の shape モード + パレット（色を 4 bit に）  |
| ピクセルアート風のモザイク                  | `PIXEL`（25 – 130 B）                            |

playground のデフォルト `TRIANGLE n=64 / baseSize 512 / RGB-565` は妥当な出発点です。バイトを減らしたいなら `n` を下げ、絶対最小サイズなら `DCT` に切り替えます。

## thumbhash / sqip との関係

**thumbhash**（Evan Wallace、2023）は blurhash の後継。同じアイデア（DCT エンコードのぼやけたサムネイル）を、よりタイトなビットレイアウトで、1 枚あたり ~24 バイト、純 JS で実装したものです。arthash の `DCT` モードは同じニッチを狙います。

**sqip**（Tobias Baldauf、2017）は Node のプラグインフレームワーク。最もよく使われる `sqip-plugin-primitive` は Go の [`primitive`](https://github.com/fogleman/primitive) バイナリを呼び出し、画像に N 個の幾何形状を山登りで配置して SVG を書き出します。典型的な使い方はビルド時生成、HTML に LQIP としてインライン埋め込み。arthash の shape モードは sqip の primitive 部分を狙いますが、ブラウザ wasm でネイティブに動作するため、リクエスト時のエンコードも可能です。

### 機能比較

| 機能                              |     arthash     |        thumbhash        |          sqip           |
| --------------------------------- | :-------------: | :---------------------: | :---------------------: |
| DCT ぼやけサムネイル（17–24 B）   |        ✅        |            ✅            |            ❌            |
| 幾何 SVG プリミティブ             |   ✅ 5 種類      |            ❌            |   ✅ 複数プラグイン       |
| ピクセルモザイク                  |        ✅        |            ❌            |            ❌            |
| 外部パレット（色 → 4 bit）        |        ✅        |            ❌            |            ❌            |
| Potrace 風 SVG トレース            |        ❌        |            ❌            | ✅ `sqip-plugin-potrace` |
| WebP 出力                         |        ❌        |            ❌            |   ✅ 一部プラグイン        |
| 任意出力サイズへのデコード        |        ✅        |    ⚠️ デフォルト ~32 px   |     ✅（SVG ベクター）     |
| Web / ブラウザ wasm               |        ✅        |        ✅ 純 JS          | ❌（Go 子プロセス必要）    |
| Python バインディング             |  ✅ PyO3 wheel   | ⚠️ 純 Python 80× 遅い    |            ❌            |
| Rust crate                        |        ✅        |            ✅            |            ❌            |
| デプロイ形態                      | リクエスト / ビルド時 | リクエスト / ビルド時 |    ビルド時のみ          |

arthash は sqip の Potrace トレースモード（ビットマップ輪郭 → SVG パス）や WebP / data-URI 出力には**対応していません**。必要な場合は sqip の方が適しています。

## arthash が bit を節約する仕組み

すべての bit が画像情報に費やされ、ヘッダーオーバーヘッドはゼロ。節約は 4 層に分かれます：

1. **ヘッダーなし — 両端合意の Codec。** バイトストリームは自己記述的ではなく、マジックナンバー、モードタグ、ビット幅は持ちません。モード、形状数、量子化ビット幅、パレットはすべて `Codec` に格納され、エンコードとデコードの両方に渡されます。
2. **ビットパッキング、最終バイトはゼロパディング。** LSB-first。ハッシュ長は codec で完全に決定されます。
3. **DCT モード — 周波数領域 + 知覚空間での二重圧縮。** Oklab 量子化、`AB_SCALE = 5`、符号付きべき乗 compander、三角形高周波マスク、チャンネル別適応 AC スケール。
4. **Shape / PIXEL — 幾何と色の細やかな節約。** 対数スケール半径量子化、RGB-565 / パレット選択可能、離散 alpha レベル、π-対称 theta + ハーフステップバイアス。

バイト形式は [`docs/SPEC.md`](https://github.com/Jannchie/arthash/blob/main/docs/SPEC.md) に固定されています。
